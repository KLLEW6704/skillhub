# SkillHub MVP 系统设计

## 1. 目标与定位

SkillHub 是面向高校学生与校园组织的技能实践和项目协作平台。第一版通过真实可运行的前后端完成以下成长闭环：

> 注册登录 → 创建技能 → 上传作品 → 申请校园项目 → 被录用并完成项目 → 获得评价 → 技能等级自动成长

系统强调“可展示、可验证、可成长的技能资产”，不采用商品交易平台的表达方式。预算字段用于说明项目条件，不实现支付、订单或资金托管。

## 2. MVP 范围

### 2.1 包含功能

- 学生、需求方、管理员三类用户的登录与角色权限。
- 学生和需求方开放注册；管理员与三类演示账号由初始化脚本提供。
- 学生基本资料、技能标签、技能等级、成长积分、作品和项目经历。
- 图片、视频和常见文档的本地文件上传。
- 需求方创建项目，管理员审核项目，公开项目大厅展示通过审核的招募项目。
- 学生申请项目，需求方查看申请、录用成员、推进项目状态。
- 需求方在项目完成后对被录用学生进行四维评价。
- 评价、作品和已完成项目共同计算每项技能的成长积分与等级。
- 管理员数据概览、用户列表与状态管理、项目列表与审核管理。
- 推荐项目、热门技能和优秀学生组成的首页展示。
- 响应式界面、中文校验错误、加载状态、空状态和操作反馈。

### 2.2 不包含功能

- 项目任务看板、实时聊天、站内通知和协作文件空间。
- 举报处理工作流。
- 支付、订单、担保或结算。
- AI 需求分析、AI 技能匹配和 AI 成长顾问。
- OSS、对象存储或第三方视频转码。
- 专业资格认证或学校官方认证。

## 3. 技术方案

项目采用单仓库前后端分离结构：

- `frontend/`：React、TypeScript、Vite、Tailwind CSS、React Router、TanStack Query。
- `backend/`：FastAPI、SQLAlchemy、Pydantic、JWT、密码哈希、本地静态文件服务。
- `backend/skillhub.db`：SQLite 数据库，启动时通过迁移或初始化逻辑创建结构。
- `backend/uploads/`：本地上传目录，只提交 `.gitkeep`，不提交运行时文件。
- `docs/`：设计、实施计划和项目说明。

前端通过 `/api/v1` REST API 调用后端。API、业务服务和数据访问保持分层，使后续可将 SQLite 切换为 PostgreSQL，也可在独立 `agents/` 服务模块中增加 AI Agent，而无需重写页面与核心数据模型。

## 4. 角色与权限

### 4.1 学生

- 浏览公开项目与其他学生的公开技能主页。
- 编辑自己的学生资料、技能和作品。
- 申请处于招募中且未过截止日期的项目。
- 查看自己的申请状态、项目经历和评价。
- 不能发布项目、审核项目、录用申请者或评价其他学生。

### 4.2 需求方

- 浏览公开内容并维护组织资料。
- 创建、编辑自己的待审核项目。
- 查看自己项目的申请者并接受或拒绝申请。
- 将已有录用成员的项目从招募中推进到进行中、待评价和已完成。
- 只对自己项目中已被录用的学生评价，且每个项目对每位学生只能评价一次。
- 不能申请自己或其他需求方发布的项目，不能修改其他需求方项目。

### 4.3 管理员

- 查看平台用户、项目、申请和完成情况统计。
- 启用或停用用户。
- 审核通过或拒绝待审核项目。
- 查看全部项目的审核状态与生命周期状态。
- 不替代需求方完成申请录用和评价操作。

## 5. 页面结构

### 5.1 公共页面

- 首页：价值主张、推荐项目、热门技能、成长学生、平台闭环。
- 项目大厅：关键词、技能、分类、截止时间筛选与分页。
- 项目详情：项目介绍、技能要求、预算、截止日期、发布方、申请状态和申请入口。
- 技能大厅：按技能和关键词筛选公开学生画像。
- 学生公开主页：资料、技能等级、作品、项目经历、综合评价。
- 登录、注册、403、404 页面。

### 5.2 学生工作台

- 概览：技能成长、申请状态、最近评价。
- 资料编辑：头像、姓名、学校、学院、专业、年级、个人介绍。
- 技能管理：新增、编辑、删除技能并查看积分来源。
- 作品管理：上传文件、关联技能、填写标题与说明。
- 我的申请：按待处理、已接受、已拒绝、已完成查看。

### 5.3 需求方工作台

- 概览：项目数量、待处理申请和已完成项目。
- 发布项目：名称、说明、分类、所需技能、截止日期、预算。
- 我的项目：审核状态、生命周期状态和可执行操作。
- 申请者管理：查看申请留言、学生技能与作品，接受或拒绝。
- 项目评价：对已录用学生填写四项 1–5 分和文字评价。

### 5.4 管理后台

- 数据概览。
- 用户列表与启用/停用操作。
- 项目列表与审核通过/拒绝操作。

- `created_at`

### 6.2 StudentProfile

- `display_name`
- `avatar_url`
- `bio`

### 6.3 RequesterProfile

- `id`
- `user_id`，唯一外键
- `organization_name`
- `organization_type`
- `description`

### 6.4 Skill

- `id`
- `user_id`
- `name`
- `description`
- `growth_score`，由后端计算并保存
- `level`：`1 | 2 | 3 | 4`

### 6.5 Portfolio

- `id`
- `user_id`
- `skill_id`
- `title`
- `description`
- `file_url`
- `file_type`
- `created_at`

作品必须属于当前学生的一项技能，使作品积分能够准确进入具体技能。

### 6.6 Project

- `id`
- `creator_id`
- `title`
- `description`
- `category`
- `budget`
- `deadline`

### 6.7 ProjectRequiredSkill

- `project_id`
- `skill_name`

### 6.8 Application

- `id`
- `project_id`

- `message`

### 6.9 Review

- `id`

- `skill_score`
- `communication_score`
- `delivery_score`
- `time_management_score`

- `created_at`

数据库唯一约束保证同一项目对同一学生只有一条评价。

## 7. 项目生命周期

1. 需求方创建项目，`audit_status=pending`。
2. 管理员通过后，项目进入公开的 `recruiting` 状态。
3. 学生申请，生成 `pending` 申请。
4. 需求方接受一个或多个申请，未被选择的申请可逐一拒绝。
5. 至少存在一名已接受学生后，需求方开始项目，进入 `in_progress`。
6. 需求方结束执行阶段，进入 `awaiting_review`。
7. 需求方对每位已接受学生评价；该学生申请状态变为 `finished`。
8. 所有已接受学生均已评价后，项目自动变为 `completed`。

服务层校验项目所有权、角色、审核状态、截止时间和前置状态。状态转换不允许跳步。

## 8. 技能成长算法

每项技能独立计算成长积分：

```text
growth_score = 该技能作品数 × 10
             + 匹配该技能的已完成项目数 × 20
             + 匹配项目评价的四维平均分总和 × 3
```

项目所需技能名称与学生技能名称采用去除首尾空白后的不区分大小写匹配。一个项目可以为学生的多项匹配技能贡献积分，但同一技能在同一项目中只计一次。

等级阈值：

- 0–19：Lv1 兴趣者
- 20–59：Lv2 作品证明
- 60–119：Lv3 项目实践者
- 120 及以上：Lv4 优秀贡献者

新增或删除作品、创建或撤销评价、项目完成状态变化后，后端调用统一成长计算服务回算受影响的技能。前端不自行计算等级，只展示后端返回的积分、等级和积分来源。

## 9. API 边界

API 统一使用 `/api/v1` 前缀：

- `/auth`：注册、登录、当前用户。
- `/profiles`：学生与需求方资料、公开学生主页。
- `/skills`：学生技能 CRUD、技能统计。
- `/portfolios`：作品上传、列表和删除。
- `/projects`：公开项目、项目详情、需求方项目 CRUD、状态转换。
- `/applications`：申请、我的申请、申请接受与拒绝。
- `/reviews`：创建评价、学生评价列表、评价汇总。
- `/admin`：统计、用户管理、项目审核。
- `/uploads`：只读静态文件访问。

路由只处理参数、认证和响应转换；业务规则集中在服务层；数据库查询集中在仓储或明确边界的数据访问函数中。

## 10. 认证与安全

- 密码使用强哈希算法保存，不保存明文。
- 登录成功返回短期 JWT，前端保存登录状态并在 API 请求中携带 Bearer Token。
- 后端从 JWT 解析用户并再次检查 `is_active` 与角色，前端路由守卫只用于用户体验，不作为安全边界。
- 所有修改接口校验资源所有者。
- 文件名由服务端生成，禁止使用用户原始路径，避免目录穿越。
- 上传允许图片、视频、PDF、Word 和 PowerPoint 常见格式，默认单文件最大 20 MB。
- 生产说明会提示更换密钥、使用 PostgreSQL、对象存储和 HTTPS；课程演示默认配置不冒充生产安全配置。

## 11. 错误处理

- Pydantic 负责字段类型、长度、分值范围和日期格式校验。
- 业务服务抛出统一领域错误，映射为 400、403、404、409 等 HTTP 状态。
- 前端 API 层将错误转换为中文消息，表单字段错误显示在对应输入项下。
- 401 清除失效登录状态并跳转登录页；403 展示无权限页面；404 展示资源不存在页面。
- 网络加载、空列表、上传中、提交成功和失败均有可见状态，禁止静默失败。

## 12. 视觉设计

采用“成长档案馆”方向：

- 主色为墨绿，背景为暖米白，成长数据使用琥珀色，评价和提醒使用克制的砖红色。
- 页面具有学院刊物和成长档案的可信感，通过编号、细线、纸张层次和不对称栅格形成识别度。
- 标题优先使用中文衬线字体，正文使用清晰的中文无衬线字体，并设置离线回退字体。
- 避免紫色渐变、玻璃拟态大卡片、过度圆角和电商式价格强调。
- 动效集中在首页入场、卡片悬停、进度变化和操作反馈，尊重减少动态效果偏好。
- 桌面端优先，同时保证 375px 手机宽度下导航、表单、列表和详情可用。

## 14. 演示数据与交付

初始化脚本提供：

- 一个管理员账号。
- 至少两个学生账号，包含不同技能、作品、项目经历和评价。
- 一个需求方账号与组织资料。
- 若干已审核、待审核、进行中和已完成项目，用于展示不同状态。

交付物包括源代码、数据库初始化与演示数据脚本、环境变量示例、README、测试和本设计文档。默认启动方式为分别启动 FastAPI 和 Vite；README 同时提供 Windows PowerShell 命令。

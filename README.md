# SkillHub

SkillHub 是一个面向高校实践场景的技能成长与项目协作平台。它把学生的作品、AI 辅助答辩、人工核验和真实项目交付串成一条可追溯的成长链路，让项目方能够找到合适的人，让学生能够用持续的证据证明自己的能力。

当前版本是课程实践与产品原型，不是学校官方认证系统。系统中的徽章、AI 结果和种子数据都会明确标注为 SkillHub 演示或试行内容。

## 一分钟启动演示

环境要求：Windows、Python 3.11+、Node.js 20+。

1. 从 GitHub 克隆 `codex/skillhub-ai-portfolio-core` 分支。
2. 双击项目根目录的 `start-demo.cmd`，或双击中文入口 `一键启动演示.bat`。
3. 脚本会准备运行环境、安装依赖、生成模拟数据，并启动前端和后端。
4. 浏览器打开 <http://127.0.0.1:5173/>。

第一次启动需要网络安装依赖，可能需要几分钟。演示期间请不要关闭后端和前端窗口；结束时关闭这两个窗口即可。

如果自动准备失败，可以先双击 `setup-demo.cmd`，完成后再双击 `start-demo.cmd`。

## 核心业务流程

### 学生技能档案

- 编辑公开个人资料，包含学校、学院、专业、年级、个人介绍等信息。
- 管理技能，支持新增、编辑、删除，并显示成长活跃度与等级进度。
- 在学生工作台预览项目方看到的公开档案。

### 作品集与证据核验

作品证据现在以“作品集”呈现。学生可以保存草稿，填写创作背景、本人职责、制作过程、迭代说明、关联技能和可见范围。

支持的作品类型包括：视觉海报、数据可视化、代码项目、内容文档和运营执行记录。

证据可设置为仅自己可见、仅授权项目可见或公开展示。公开档案只展示公开作品和已经完成人工核验的结果。

核验链路为：

```text
作品草稿 → 学生提交 → AI 动态答辩 → AI 辅助初评 → 管理员分配审核员 → 人工核验 → 通过后公开
```

AI 只负责整理可观察事实、指出证据缺口、生成追问和提供初评分。未完成人工核验的 AI 结论不会自动发布到公开档案。

审核员可以优先查看 AI 标记的疑点，例如作品与描述不一致、个人贡献说明不足、答辩回答含糊、证据缺口和评分异常，从而把时间集中在需要人工判断的部分。最终是否通过、如何调整分数，都必须由审核员填写理由并确认。

### 多岗位项目协作

项目方可以：

- 填写项目名称、目标、交付物、验收标准和截止时间。
- 让 AI 根据项目 brief 生成岗位和任务草案。
- 编辑岗位名称、岗位类别、岗位职责、所需技能、岗位交付物和招募人数。
- 将大项目拆成任务链路，跟踪“未完成、处理中、已完成”。
- 保存未完成的项目发布草稿，稍后继续编辑。
- 从技能大厅查看学生档案，并发出项目邀约。

岗位类别包括：设计、代码开发、数据分析、内容创作、运营执行和通用协作。项目拆解结果会优先返回简体中文；AI 生成内容仍需项目方确认后才能发布。

### 项目邀约、申请与协作空间

- 项目方可以从学生公开档案右上角发出邀约。
- 学生在工作台收到邀约，查看项目详情后自主决定是否申请。
- 学生和项目方共享同一套项目任务状态。
- 学生只能更新自己负责的任务或本岗位任务，项目方可以管理整体进度。
- 任务状态变更会保留更新人、版本和变更记录，避免多人同时编辑时覆盖彼此的修改。

### 项目完成与岗位评价

项目结束后，项目方可以按岗位类别评价学生。不同岗位使用不同评价量表：

| 岗位类别 | 评价维度示例 |
| --- | --- |
| 设计 | 需求与方案、设计执行、协作沟通、交付规范 |
| 代码开发 | 功能正确性、代码质量、测试与可靠性、协作交付 |
| 数据分析 | 数据质量、分析方法、结果解释、可复现交付 |
| 内容创作 | 内容准确性、结构表达、受众适配、协作交付 |
| 运营执行 | 方案规划、组织协调、现场执行、复盘改进 |
| 通用协作 | 专业表现、沟通协作、成果交付、时间管理 |

学生公开档案会把“成长活跃度、公开作品集、项目经历”作为三个大板块。真实项目记录和项目方评价会合并展示，方便查看一次完整的实践经历。

## 手动启动

### 后端

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m app.seed
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

后端地址：<http://127.0.0.1:8000>
接口文档：<http://127.0.0.1:8000/docs>
SQLite 数据库：`backend/skillhub.db`
上传文件：`backend/uploads/`

### 前端

另开一个 PowerShell：

```powershell
cd frontend
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run dev -- --host 127.0.0.1
```

前端地址：<http://127.0.0.1:5173>

## AI 配置

AI 项目拆解和作品辅助评估使用 DashScope 的 OpenAI 兼容接口。把密钥放在 `backend/.env`，不要提交到 GitHub：

```dotenv
DASHSCOPE_API_KEY=你的密钥
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
DASHSCOPE_MODEL=qwen3.7-flash
```

只查看模拟数据、演示项目协作和浏览公开档案时不需要 API Key。没有配置密钥时，真实 AI 请求会明确返回配置错误，不会伪造评估结果。

## 模拟数据说明

模拟数据由 `backend/app/seed.py` 生成，脚本可以重复运行，不会重复创建同一批演示记录。它会生成：

- 演示账号和角色权限
- 学生技能与成长活跃度
- 公开作品集与演示图片
- AI 动态答辩、AI 初评和人工核验结果
- 招募中、进行中和已完成项目
- 多岗位、任务链路、邀约、申请和项目评价

数据库文件和上传文件不提交到 GitHub；队员运行种子脚本即可得到同样的演示环境。

## 安全与边界

- `.env`、SQLite 数据库、上传文件和本地依赖不会提交到仓库。
- 公开页面不会展示未完成人工核验的 AI 结论。
- 私密作品只有在学生明确授权后，项目方才能在对应流程中查看。
- 项目邀约不会自动录用学生，学生必须主动查看项目并申请。
- 当前版本是课程实践原型，尚未包含生产级对象存储、支付、即时聊天、学校官方背书和自动录用。
- 生产部署前需要更换 JWT 密钥、启用 HTTPS、限制跨域、加强上传文件安全检查，并迁移到受管数据库和对象存储。
